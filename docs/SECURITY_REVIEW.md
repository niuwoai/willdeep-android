# Android 安全边界与核查记录

核查日期：2026-10-21。Android 版本：1.26.0-rc5（123）。官网：[willdeep.com](https://willdeep.com)。

## 本次修复

- WebSocket 正文不再写入日志，解析失败仅返回固定错误；推送处理不记录原始异常内容或供应商错误文本。
- 扫码、历史配对、健康检查、配对申请和 WebSocket 连接均执行传输策略：网络端点必须使用 HTTPS；只允许字面量 `127.0.0.1` / `::1` 作为设备本机明文测试地址。禁止 URL 用户名、密码和查询参数。
- OkHttp 禁止 HTTP 与 SSL 自动重定向；不绕过系统证书校验。Android Network Security Config 同时禁用其他目标的明文传输。
- 旧 HTTP 配对不会被删除或静默升级 URL；应用停止尝试不安全连接，提示扫描安全中继或 HTTPS 网关二维码。HTTP 回退地址被过滤。
- `allowBackup=false`，并对旧备份规则、Android 12+ 云备份及设备迁移明确排除所有应用数据域。覆盖升级保留本机数据；换机重新配对。

## Android Git 历史

使用 Gitleaks 8.30.1 默认规则扫描 `git log --all` 可达的分支、远端引用和 tag，初始覆盖 87 个提交、约 1.15 MB 的提交补丁；同时核对敏感文件名历史。

- 未发现真实凭据；不代表数学意义上保证不存在未知格式秘密。
- 初始扫描有一项 `generic-api-key` 告警，位于历史单元测试。核对为按顺序排列的十六进制字符重复两遍，且只用于配对字段解析和断言，不是实际中继令牌。
- `.gitleaksignore` 仅记录这一项确切提交、路径、规则和行号的指纹；不按目录或任意 token 字段放行。原始脱敏报告保存在本机 `build/security-audit/`，不提交会话或设备数据。
- `.signing/`、`*.jks`、`*.keystore`、`local.properties` 未出现在已核查的可达提交路径中；正式更新继续复用原签名密钥。

复查命令（需先安装 Gitleaks）：

```bash
gitleaks git . --log-opts="--all" --redact=100
gitleaks git . --staged --redact=100
```

如未来发现真实密钥，应首先撤销或轮换，再评估清理历史。单纯删除当前文件无法撤销已有泄露。

## 桌面授权检查

核对 Mac `6eef64ed`、Rust `dbc4f6c` 的发布源码；桌面端未因本次 Android 发布改动。

| 范围 | 核查内容 |
|---|---|
| Mac 本地网关 | 配对信息、轮换及设备管理要求 desktop token；配对码有期限并且一次性领取；WebSocket 校验桌面/设备身份，设备撤销后断开连接 |
| Mac 命令执行 | 手机命令经过宿主路由和配置字段白名单；文件读取使用真实路径及工作区限制；工具回答/确认和补丁应用仍经过宿主现有处理流程 |
| Rust Runtime | 字面量命令白名单；拒绝未登记工作区创建会话；拒绝不支持的命令；审批只允许一次或拒绝；请求幂等、只读工作区限制保留 |

配对手机属于受信任远控端，可在宿主允许范围内调整模型和审批模式（包括完全访问）。这不是多租户隔离或访客只读权限；设备凭据泄露必须视为电脑远控凭据泄露处理。

公网中继与本地网关不是同一个认证系统。中继使用 room/token 作为通道凭据，HTTPS/WSS 保护传输，但当前协议没有应用层端到端加密。本次验证不等于已审计第三方中继生产服务，也不能把本地网关的逐设备撤销结果直接套用到中继。

## 验证与范围

- Android Release 单元测试覆盖不安全 URL、历史凭据、回退过滤及重定向不转发配对数据；原有协议解析和连接测试继续执行。
- Release lint、签名、包版本及 APK 对齐由 `scripts/release_android.rb` 验证，报告随发布提供。
- 真机仪器测试针对正式签名安装包检查系统备份开关及公网/局域网明文策略。
- 本次检查不是完整渗透测试，不涵盖 root 手机、恶意系统证书、第三方 SDK 内部实现或未知服务端漏洞。HTTPS 不保证二维码目标本身可信。

具体测试数量、手机安装结果和发布摘要以版本发行附件及本机验收报告为准。
